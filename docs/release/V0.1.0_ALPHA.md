# OpenNumLab v0.1.0-alpha

**Development preview — release preparation.** These notes describe the proposed
first public scope. A downloadable binary, its checksums and its installed results
have not yet been declared here. Use the [source quickstart](../../README.md#start-it)
to try the current code. Package assembly and final source/payload review remain
separate release steps.

OpenNumLab combines a Rust scientific desktop and CLI with an external GNU Octave
runtime. The long-term goal includes MATLAB-compatible code/files and familiar
interaction, a Rust-native execution engine, scientific packages and simulation.
This preview covers selected workflows. There is no general MATLAB/Simulink
compatibility or comparative performance claim.

## What is implemented

| Area | Alpha scope and evidence boundary |
| --- | --- |
| Desktop | Current Folder, Editor, Command Window, Workspace, history and figure previews. Selected earlier GUI journeys were observed; current release-app GUI/focus/shortcut parity remains unqualified. |
| Octave execution | Persistent sessions, original-source preparation, diagnostics, streaming output, selected workspace inspection/editing and recovery. Optional native input/debugger/value routes require their matching adapters. Source/native regressions and earlier installed CLI checks exist; a rebuilt package needs its own acceptance. |
| Graphics | Octave-generated figure previews and selected live-object/property APIs. Local Core5/Graphics6 checks exercised Stop, clear and restart with safe and whitespace temporary roots, retaining and decoding 24 PNGs. This is selected-host evidence, not general graphics or visual parity. |
| Files and scientific packages | Original MAT round-trip and numerical/scientific fixtures exercise declared types and APIs. Optional packages stay separately installed. An Octave self-round-trip does not prove MATLAB file interchange or toolbox equivalence. |
| Rust arithmetic | Explicit `mathlab eval --backend rust` supports bounded real double-array arithmetic without fallback. Selected operator, language, array and CLI regressions passed locally. |
| Rust library APIs | Persistent variables/`ans`, owned snapshots and transactional errors/cancellation are tested at the session API. A bounded discrete-accumulator simulation library has 22 passing tests. These APIs do not enable a persistent Rust CLI/desktop route or a general simulation editor. |

The [README](../../README.md) contains command examples, optional adapter setup
and the current application shortcuts. The [compatibility guide](../../compatibility/README.md)
defines the checked fixture subsets. Passing tests establish those cases on the
recorded runtime, rather than a percentage of MATLAB coverage.

## Installation and builds

The package target currently being qualified is macOS on Apple silicon, with
GNU Octave installed separately. Source builds need a compatible Rust toolchain
(workspace minimum 1.88), locked Cargo dependencies, a compiler/linker and platform
libraries. Graphics also needs a working toolkit/fonts; the usual local profile
uses gnuplot. Linux source builds have setup guidance, while current public
installed-platform qualification remains pending. Native Windows engine startup
is unsupported.

Use the [README quickstart](../../README.md#start-it) for a checkout or the
[archive build recipe](SOURCE_ARCHIVE.md#ordinary-builds-after-extraction) for
Git-free source. The [packaging guide](DEVELOPMENT_ALPHA.md) explains local macOS
assembly, external runtime and adapter ABI requirements, writable project state
and provenance. The alpha bundle remains unsigned unless a separately identified
artifact establishes signing/notarization. A clean source build is not a
clean-machine installation test.

## Known gaps

- **Edited Save → Run needs an installed regression.** An older app executed stale
  saved source after a debugger journey. A later source repair passed local
  regressions; that does not pass the new app's GUI journey. The failed historical
  result is retained in the packaging guide.
- **Release installation remains under validation.** The new package needs its
  own installed CLI, read-only relocation, current-executable/tamper and final
  payload checks. Clean-machine installation, upgrade/removal, GUI recovery and
  trusted public installation are not established by earlier candidates.
- **Interface compatibility is incomplete.** Familiar panel roles and current
  bindings do not establish MATLAB muscle-memory compatibility across shortcuts,
  focus, dialogs, layouts or debugger actions.
- **Language, files and toolboxes have limits.** Modern MATLAB types, classes,
  indexing variants, live documents/apps and specialized toolboxes need further
  implementation and conformance. MATLAB file interchange is assessed per format
  and type; optional Octave packages are separate projects.
- **Graphics and native modules are configuration dependent.** The decoded PNG
  checks cover selected configurations on one host. Full interactive figure
  editing, glyph fidelity, arbitrary path variants and cross-platform behavior
  remain open. Native modules must match the external runtime's OS, architecture
  and ABI.
- **Rust execution is experimental.** Its bounded arithmetic profile rejects
  functions, scripts, indexing, complex values and other unsupported syntax.
  Persistent Rust CLI integration is outside this proposed alpha source scope. The
  simulation library has no model canvas, general block graph, continuous solver
  or Simulink import.
- **Build and release evidence is distinct.** Hosted CI for the final revision,
  offline dependency/source closure, binary reproducibility and final notices
  review remain separate. The recorded upstream `dispatch` notice gap is explained
  in [THIRD_PARTY.md](../../THIRD_PARTY.md).
