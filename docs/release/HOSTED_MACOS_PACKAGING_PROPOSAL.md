Remaining included account quota is **unknown**. Read-only GitHub probes confirmed `me-farza` but returned no account plan; current and legacy Actions billing endpoints returned HTTP 404 with a missing `user` scope notice. Null/404 does not mean zero usage or available allowance. The current billing API requires user Plan(read) access and provides usage data, not a reserved job allowance. No auth refresh was attempted. A public documentation allowance or one repository's timing report cannot establish that balance. No extra spend or billing change is proposed. [Billing API](https://docs.github.com/en/rest/billing/usage#get-billing-usage-summary-for-a-user).

Use one literal standard runner, preferably `macos-26` after the runtime preflight below. GitHub currently documents standard `macos-15` and `macos-26` as arm64 M1, 3 CPU, 7 GB RAM and 14 GB SSD for private repositories; included allowance can apply, with overage thereafter. Avoid `-large`, `-xlarge`, `-intel` and moving `macos-latest`. No assumption about a historical minute multiplier is needed. Record actual image, OS, architecture, Xcode/SDK and compiler identities rather than treating the label as an immutable image. [Runner reference](https://docs.github.com/en/actions/reference/runners/github-hosted-runners), [runner pricing](https://docs.github.com/en/billing/reference/actions-runner-pricing).

To keep one manual run to one job without expanding the source export's two configuration exceptions, propose a gated job inside the already reviewed `.github/workflows/ci.yml`. Add `workflow_dispatch` input `package_macos` default false, plus expected full source commit and local runtime SHA inputs. Packaging is eligible only for manual dispatch with that flag; existing jobs skip only for that explicit packaging mode. Normal push/PR/check dispatch behavior stays unchanged. Use `contents:read`, no matrix, no signing/publishing action, one serial concurrency group and a 60-minute job limit. Keep the workflow proposal in documentation until separately authorized and reviewed. Do not create an active workflow file now.

The proposed packaging condition is `${{ github.event_name == 'workflow_dispatch' && inputs.package_macos == true }}`; existing jobs use its negation. The expected commit/runtime inputs may be empty for ordinary checks but are strictly validated before a packaging checkout. This prevents a manual packaging request from also launching the ordinary test matrix/native jobs.

The requested full source commit must equal the dispatch event's immutable SHA and contain the reviewed harness/configuration. Checkout that exact SHA with credentials persistence disabled and full shallow-free standalone history, then assert HEAD and clean status. Record workflow SHA, source SHA, upstream export mapping and resolved action commit SHAs. A new source correction is required for the [current Octave 8.4 failure](PRIVATE_CI_38797002764.md); do not describe the present source CI as green.

## Job sequence and bounds

| Phase | Proposed behavior |
| --- | --- |
| Setup | Validate input/commit/private destination; capture platform/image/toolchain and formula metadata. No cache seed or existing target reuse. |
| Dependencies | Ten-minute step cap. Approved matching bottles only; runtime executable-hash preflight above. |
| Capacity | After setup require at least 8 GiB free on both build-temporary and output filesystems. This is a conservative unmeasured starting floor, not a proven peak. If unavailable, stop without deleting SDKs/caches. |
| Assembly | Run unchanged `bash scripts/package-macos.sh --with-debugger --output "$RUNNER_TEMP/package-output/OpenNumLab-alpha-<full-sha>-native.app"` with jobs=2/incremental=0. No dirty/prebuilt/skip-build option. |
| Guard | A proposed supervisor logs elapsed time/free space and owns/tracks every packaging/Cargo/native session. It must stop and drain all owned sessions after 45 minutes or below 1 GiB free. Killing only the outer group is insufficient: the current packager starts its commands with `start_new_session=True`. Leave time before the 60-minute job deadline for evidence; capture df before/after and phase times. Reliable session registration/cleanup and bounded synthetic termination tests are prerequisites to activation. |
| Verification | Require normal assembly validation; optionally run the packaged-source installed CLI harness against that same resolved build runtime in a fresh owned report/project directory with a three-minute step cap. No GUI/full native suite is implied. |
| Transport | Tar only the validated app and selected evidence, verify a fresh extraction with the same payload validator, hash the outer tar, then upload. Do not upload Cargo target, registry, checkout metadata or dependency source trees. |

Retain an owned launch log from the first phase and upload controlled-failure evidence with `if:always()`. Upload the app only after successful assembly and transport verification. Provider cancellation may leave only Actions logs; do not promise recovery from a hard runner timeout. The guard must terminate descendants, avoid source/cache deletion and report a failed/incomplete build rather than retrying automatically.

The resource guard is not implemented by this proposal. A concrete patch should monitor/register subprocesses at the packager's existing `run` launch boundary, where each actual session PID is known, with optional CI limits and default behavior preserved. Keep Cargo release argv, frozen-source/private-target/Cargo-home policy and acceptance checks unchanged. An external supervisor is acceptable only after it proves equivalent owned-session coverage; periodic PID sampling alone is not that proof. Synthetic tests must cover nested `setsid`/`start_new_session`, forks during shutdown, complete drain, PID identity/ownership and preservation of unrelated processes. Do not start the hosted job until this narrow guard implementation is reviewed and proven.

## Artifact and local acceptance

Use the already reviewed `actions/upload-artifact@v4` family with a unique full-SHA/OS/run-ID/attempt name, `overwrite:false`, `if-no-files-found:error`, short explicit retention (propose 7 days) and `compression-level:0` for an already compressed tar. Direct directory upload loses executable modes; tar preserves the inner modes. Repository retention was read as default 90 days/maximum 400, but account storage headroom remains unverified. [v4 artifact permissions and retention](https://github.com/actions/upload-artifact/tree/v4#permission-loss).

Deliver the app tar plus a transport receipt binding tar SHA/size, `release.json` SHA, final `checksums.sha256` SHA, source/workflow commits, run/artifact identity, runtime/bottle/SDK identities and actual guard result. Distinguish GitHub's outer artifact ZIP digest from the app tar digest. Root downloads by explicit private repository/run/artifact into a new directory, validates both transport and safe relative archive paths, then verifies every app hash/size/executable mode before launch. Existing apps/artifacts are preserved.

Before local installed acceptance, remeasure the selected runtime and require `SHA256(resolved octave-cli) == release.json.build.native.runtime_executable_sha256`. Invoke the packaged-source QA harness with that same `--octave` path and fresh owned report/project locations. The existing doctor gate remains unchanged. If hashes differ, local GUI/installed acceptance stays pending until an identical runtime is obtained and measured; hosted same-runtime CLI evidence does not bypass it.

An artifact can establish a new identified build and selected subsequent GUI observations. It does not establish full numerical/MATLAB conformance, interaction parity, binary reproduction, signing/notarization, self-contained runtime distribution, clean-machine/lifecycle acceptance or public delivery. No tag/release or repository visibility change is proposed.
