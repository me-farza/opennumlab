# Original common conformance fixtures

`common.json` declares five small, independently authored cases for the selected
MATLAB R2026b / Octave 11.3.0 profile. A profile names the requested comparison;
it is not evidence that either runtime was executed. No reference goldens ship
with these fixtures. A missing licensed reference must remain unavailable.

| Case | Declared observation |
| --- | --- |
| `exact_nd_uint64` | Exact large unsigned/signed integers; full N-D values; selected third-axis plane; value-copy isolation |
| `complex_sparse` | Double/single complex components; sparse coordinates/storage; logical and empty shapes |
| `closure_forward_local` | Forward script-local calls and retained anonymous value captures |
| `intentional_error` | `MathLab:ConformanceIntentional` with a retained typed assignment before the error |
| `mat_v7` | Full declared typed fields saved and loaded through MAT version 7; optional external file input |

Execute the same original fixture bytes in each route. MATLAB and raw Octave
drivers catch errors outside that body; the application route uses the actual
`Engine::run_file` preparation path. Raw Octave can reject the forward local call
with `Octave:undefined-function`; this named divergence must remain visible.
Passing application preparation does not make raw Octave pass that case.

Before execution, the driver initializes `result = struct()` and sets the
absolute `mathlab_conformance_work_directory`. For MAT replay, it may also set
an absolute `mathlab_conformance_mat_input`. The MAT case always writes
`conformance-values.mat` to the work directory and loads either that file or the
explicit input. A self roundtrip alone establishes no cross-runtime interchange.
Sparse logical MAT storage is outside this initial MAT subset: the local Octave
11.3.0 probe changed its storage and values on a version-7 self roundtrip. The
direct `complex_sparse` case still records sparse logical values; its success
does not qualify that file path.

Add `support/` to the runtime path, then call
`mathlab_conformance_write(output_path, case_id, result, error_identifier, error_message)`
after success or a caught error. Pass empty character vectors for both error
arguments on success. The writer publishes one UTF-8 JSON file of at most 1 MiB
using a closed temporary file in the destination directory. The driver owns
backend identity, fixture/support hashes, provenance, timeout and comparisons.

The schema-1 record has `case_id`, `outcome`, `values` and `error` alongside
`schema_version`. `values` contains alphabetically sorted named fields of the
flat numeric/logical `result` struct. Every entry records `name`, `class`, `shape`,
`storage`, `complex`, `real`, `imag`, `rows` and `columns`. Arrays always remain
JSON arrays, including singleton or empty lists. Shapes have at least two
dimensions as reported by `size`; trailing singleton dimensions follow runtime
array semantics.

Dense components flatten in column-major order. Sparse components follow
`find` order and include one-based row/column indices and the full shape; their
implicit zeros are not materialized. Real arrays use an empty `imag` list.
Logical components are strings `"0"` or `"1"`. Integer components are exact
decimal strings, including signed minimum and unsigned maximum. Conversion
uses individual bits and small decimal digits rather than floating conversion
or 64-bit division. Floating components use 17 significant digits for double,
nine for single, and explicit `"NaN"`, `"Inf"`, `"-Inf"` tokens. These are
declared numeric records, not a codec for arbitrary objects, cells or tables.

The common cases use exact comparisons, including class, shape and storage.
Floating tolerances are explicit per case. The expected error compares its
identifier; runtime-specific stack paths and formatting are observations, not
an invented semantic match. Reference execution, saved authentic reference
replay and test-only synthetic data must retain distinct provenance.

## Independent mathematical oracles

Every case names an `oracle` containing its complete expected typed record.
`build_oracles.py` constructs these from original constants and column-major
index arithmetic; it neither executes a runtime nor reads captured writer
output. The signed/unsigned boundaries, full dense values, sparse coordinates,
classes, shapes, nonfinite tokens and partial-error values are explicit. Equal
empty or malformed runtime records must not satisfy this independent contract.
These mathematical expectations are not MATLAB reference goldens.

Check their generated bytes without executing MATLAB or Octave:

```sh
python3 compatibility/conformance/build_oracles.py --check
```

## Known negative regression

`known-gaps.json` is separate from the five selected common cases. Its original
`mat_sparse_logical` fixture retains both the original and loaded typed values
before checking class, shape, sparse storage and equality. Its expected outcome
is **success**, with an independent oracle requiring both values to remain the
same sparse logical matrix. There is no unsupported-identifier exemption.

The local headless Octave 11.3.0 run failed the storage assertion: the original
was sparse logical `[3,4]` with true entries at `(1,2)` and `(3,4)`; the loaded
value was dense logical with changed values. The actual typed record and source
hashes are retained in
[`observations/mat_sparse_logical_octave_11_3_0.json`](observations/mat_sparse_logical_octave_11_3_0.json).
The observation is Octave-only; it records no MATLAB or MathLab execution. The
outer driver caught the assertion to write the failed record, so its process
exit zero does not mean the fixture passed. The conformance runner must return
nonzero for this failed expected-success case, including when two affected
routes fail identically:

```sh
target/debug/mathlab --timeout 30 --json conformance \
  compatibility/conformance/known-gaps.json \
  --output /private/tmp/mathlab-known-gaps.json
```

## Explicit reference execution and replay

The following are commands to run deliberately, not a claim of execution here.
The reference executable is supplied explicitly and must be a licensed MATLAB
matching the manifest's selected release. Fresh execution saves the complete
report, including its identified MATLAB records:

```sh
target/debug/mathlab --timeout 120 --json conformance \
  compatibility/conformance/common.json \
  --matlab /absolute/path/to/licensed/matlab \
  --output /private/tmp/mathlab-cp01-fresh.json
```

Replay those records with matching manifest, fixture, support and oracle
identities; this is a saved reference comparison rather than a new MATLAB run:

```sh
target/debug/mathlab --timeout 30 --json conformance \
  compatibility/conformance/common.json \
  --reference /private/tmp/mathlab-cp01-fresh.json \
  --output /private/tmp/mathlab-cp01-replay.json
```

A fresh reference run supplies its actual MATLAB-written MAT file to the other
routes and embeds those bounded bytes with their hash in the report. Saved
replay validates the artifact and supplies the preserved bytes again; each
consumer's outcome and independent oracle determine whether loading succeeded.
This remains saved-reference replay, rather than fresh MATLAB execution. Without
an artifact only self-round-trips are reported, and without either explicit
reference option, reference comparison stays unavailable.

Use `--strict` when requiring complete acceptance: unavailable or unsupported
comparisons make it fail after publishing the report. Reports and saved inputs
are capped at 16 MiB; split larger manifests. Per-route diagnostic capture is
bounded separately. Standalone Unix routes clean up their owned process group;
this does not qualify arbitrary detached processes or other platform runtimes.

The top-level `synthetic_test_fixture` marker is rejected as a reference even
when metadata is otherwise supplied. A rejection smoke example uses deliberately
marked test data and must finish nonzero with invalid reference status:

```sh
printf '{"synthetic_test_fixture":true}\n' > /private/tmp/mathlab-cp01-synthetic.json
target/debug/mathlab --timeout 30 --json conformance \
  compatibility/conformance/common.json \
  --reference /private/tmp/mathlab-cp01-synthetic.json \
  --output /private/tmp/mathlab-cp01-rejected.json
```

Neither synthetic test records nor these mathematical oracles may be relabeled
as an executed licensed MATLAB reference.
